## 一言で

予測モデルが前提とできないシグナルのために、予測ループを迂回して直接状態変数を書き換える独立経路が、進化的/設計的に実装される原理。

## 構造

**通常経路**: 入力 → 予測モデル（F_0） → 予測誤差 → 状態更新
**バイパス経路**: 入力 → 状態変数へ直接書き込み（予測モデルを経由しない）

バイパスが成立する条件（三条件揃った時）:
1. **進化的古さ**: 予測モデルが成立する前から機能する必要がある
2. **不確実性上限の高さ**: 事前分布が極限まで平坦（予測が役に立たない）
3. **緊急性**: 応答速度が予測ループ周期より速い必要がある

**重要**: バイパス経路は通常経路の「失敗モード」ではなく、独立インフラ。両者は共存し、異なる領域を担当する。

## 使いどころ

- 感覚系の進化的差異を説明する時（なぜ嗅覚だけが違う？）
- 予測処理系フレームワーク（FEP/Predictive Coding）の適用範囲を限定する時
- システム設計で「割り込み型」と「ポーリング型」の使い分けを決める時
- 組織の危機管理経路を設計する時
- ゲーム/映画で「予測を飛ばして直接情動を動かす」演出を設計する時

## 適用例（同型）

### 神経科学
- **嗅覚**: 視床スキップ → 辺縁系直結（記憶・情動への強制書き込み）
- **脅威検出**: Superior colliculus → 偏桃体経由（視覚情報の高速ルート）
- **対光反射・瞬目反射**: 皮質を介さない反射弓

### 物理シミュ（XPBD/PBD）
- **メインループ**: Position-Based Dynamics の制約解決（予測的）
- **コリジョン割り込み**: 接触が検出されたら次の制約解決を待たず直接位置補正

### コンピュータアーキテクチャ
- **ポーリング**: CPU が周期的にデバイスを確認（予測的）
- **ハードウェア割り込み**: デバイスが CPU に割り込み信号を送る（バイパス）

### 組織・経営
- **通常の報告ライン**: 現場 → 中間管理職 → 役員（予測的フィルタ付き）
- **緊急ホットライン**: 内部通報直通、外部監査人の直報権（バイパス）

### ゲーム・経験デザイン
- **通常の入力処理**: メニュー → 選択 → 状態変化（予測的 UI）
- **即応入力**: ボタン即反応、QTE、ホラーの突然のイベント（バイパス）
- 「息を呑む」瞬間 = プレイヤーの呼吸 γ の外部リセット

### 音楽・美学
- **共鳴型エージェンシー**: 聴衆が演奏者の時間に同期（予測的）
- **突然の不協和音・ピアニッシモの静寂**: 同期を強制中断（バイパス）

### 日本美学
- 「間（Ma）」が π_likelihood 探索を誘発するのは**予測の内部**での操作
- 「突然の雷鳴」「鹿威しの音」は**予測の外部**からの書き込み = バイパス
- この区別は既存の Ma 蒸留を拡張する

## 限界

- **全感覚モダリティでバイパスが存在するわけではない** — 視覚の主経路は視床経由。バイパスは三条件が揃った領域限定
- **バイパスの濫用はシステムを不安定化する** — 組織でホットラインが多すぎると指揮系統が崩壊する。ゲームで割り込みイベントが多すぎると没入が壊れる
- **F_?-1 層の数理的定式化は未了** — 通常の F_0 予測誤差最小化とどう異なる更新則を持つかは次の探索課題
- **「直接書き込み」が本当に直接かは疑問が残る** — 嗅覚も実は短いプレ処理を持つ可能性。「バイパスの度合い」は連続量かもしれない

## 既存フレームワークとの関係

- **FEP/Predictive Coding**: 反証しないが「精度重みは内側から制御される」という暗黙前提を壊す。F_0 の下に F_?-1 層を追加する拡張が必要
- **時間エージェンシー三形態** (2026-04-17): 共鳴型の中に「バイパス割り込みによる強制中断」を追加可能
- **能動的推論 = CP 三層の統一動的定式化** (2026-04-15): 三層（散逸×自己産生×能動的推論）にバイパス層を追加するか、三層の外側に位置付けるか未決
- **Ma = Active Inference 誘発** (2026-04-14): Ma は予測の内部、バイパスは予測の外部という二分で整理できる
